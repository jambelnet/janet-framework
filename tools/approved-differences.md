# Approved differences from the original behavior

`baseline-transcript.txt` is what the original program did. `expected-transcript.txt` is the baseline with the changes below
applied by hand. `compare.ps1` checks the current build against `expected-transcript.txt`; when a refactoring step changes
the transcript on purpose, the change is listed here first.

| # | What | Why |
| --- | --- | --- || 1 | `judo mailheaders set ...` now saves and `judo mailheaders settings` shows the new values (AppConfig.xml MailHeaders changes). Before: "The file ... already exists." and nothing was saved. | The reflection based XML editor tripped over the public static property `MailHeaders.GetMailHeaders`; the typed configuration store has no such path. |
| 2 | Socket server: a request for an unknown instruction (`nonexistent`) is answered with `nonexistent, not found.` | The old server dropped the connection without an answer in this case. |
| 3 | `{ evalBool("abc" ~> "b"); yes; no; }` is true (answers the first branch). Before: false whenever there were spaces around `~>`. | The operands were compared with their surrounding spaces ("abc " contains " b"). The web UI never writes spaces there, so it never showed. |
| 4 | The settings files (`.htaccess`, `.smtpsettings`, ...) are written in the new format (`v2:` values, random nonce, per installation key kept in `.janet.key`); the transcript shows their format and line count instead of the encrypted text, and a `.janet.key` section appears. Files of older versions are read and converted on first use. | The old encryption used a key and IV that were constants of the public source code. |
| 5 | The default weather URL contains the placeholder `APPID=YOUR_OPENWEATHERMAP_API_KEY` instead of the original author's API key (AppConfig.xml, `judo weather settings`). Until you set your own key (`judo weather set <lock>URL</lock>`) the weather functions stay empty. | A personal API key must not ship in a public repository and default configuration. |
| 6 | `/www` (without the slash) and `/` answer `301` to `/www/` (query string kept). Before: `404 Not Found`. | The web UI uses relative links, so it only works with the slash; the 404 page itself suggested `/www/`. The replay does not request these paths, so the transcript is unchanged. |
| 7 | When `judo server start`, `judo socket start` (and their synonyms) or `judo serial open` leave the service stopped, the answer has a second line `Reason: ...` with the cause and the way out (port in use, no rights, unusable address, no such device). The state commands (`status`, `state`) answer as before. The console also shows the same reasons, damaged files and unsafe settings at start-up and after commands. | Before, the reason was only in log.txt and the user saw a bare `state: False`. The replay does not cover a failing start, so the transcript is unchanged. |
| 8 | New: `judo weather key [Key]` stores the OpenWeatherMap API key in the encrypted settings (`.weathersettings`); an older AppConfig.xml that has a real key in the weather URL is moved there at start-up and the URL keeps `APPID=YOUR_OPENWEATHERMAP_API_KEY`. `judo help` shows the new topic 11.3. | The key was the only secret kept in plain text. |
| 9 | The data folder is no longer the program's folder by default (see README, *Where jaNET keeps its files*): `JANET_HOME` / `--root` name it, an existing AppConfig.xml where older versions kept it stays in use, a new installation gets a folder of its own. The replay sets `JANET_HOME` to its run folder. The web UI is served from the `www` next to the program unless the data folder has its own `www`. | Data next to the program breaks services (read-only program folder), updates and backups. |
| 10 | The web server is Kestrel instead of HttpListener, and can serve https: `judo server https on [port] \| off \| status \| cert [file.pfx] [password] \| cert default` (AppConfig.xml `HttpsPort`, `Certificate`; the password is kept encrypted in `.tlssettings`; without a file jaNET makes a self-signed certificate once and keeps it in `.janet.cert.pfx`). With https on, the plain port serves this computer only and answers everybody else with `301` to https. A wrong web login answer is delayed by a quarter of a second and compared in constant time. Listening on an address other than localhost no longer needs administrator rights on Windows. The web server needs the ASP.NET Core runtime. `judo help` shows topics 6.7 and 6.8. | HttpListener cannot do https without `netsh` and administrator rights on Windows; the rest of the web behavior (urls, status codes, content types, basic auth, the replay of every http case) is unchanged. |
| 11 | New: an MQTT client (`judo mqtt ...`, section 13 of `judo help`; the Help chapter is now 14), the functions `%mqtttopic%`, `%mqttpayload%`, `%mqttnumber%` (reduced to letters, digits and `. , : _ / + @ # = -`) and an `Mqtt` section in AppConfig.xml (off unless `judo mqtt start` was used; the login is kept encrypted in `.mqttsettings`). | ESP32, Tasmota, ESPHome, Zigbee2MQTT and Home Assistant all speak MQTT. |
